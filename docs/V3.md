# Instant Wallet v3 — plan

A passkey smart wallet you open on your phone and use at once (scan, send, done), that you later
harden with a **wedgie** (wedgie.dev) as its cold-storage owner. Two P-256 signers, one contract:

| signer | role | signs | limit |
|---|---|---|---|
| passkey (Face ID / Touch ID) | hot: owner until a wedgie is paired, then spender | WebAuthn assertion over the digest | e.g. $100/day once demoted |
| wedgie (Trust M chip; github.com/clawdbotatg/clawd-trust-m — attestation not needed) | cold: owner | raw 32-byte digest, after a physical A press | none |

Domain: **instantwallet.io** (passkeys are bound to it forever). Chains: **Base + Ethereum**, any token.
Look: wedgie.dev's (white plastic, `#1a1b1a` ink, `#22c452` green, `#e3312c` red, `#a9aaab` grey,
`#f4f4f1` paper, Nunito 900 headings, DM Mono, the green/grey/red waistband).

## Why we decide the contract now

A wallet's address = f(factory, passkey). Changing the factory or the domain later strands every
user's funds behind a move. So phase 1 ships the **final** contract with only the passkey in use.

## Contract v3 (from v2, `packages/foundry/contracts/InstantWallet.sol`)

Keep: P-256 signers with kind (WebAuthn | raw) and role (owner | spender), per-asset rolling 24h
limits, `metaTransfer` / `metaExecute`, admin as `metaX` + self-calls, one EIP-712 digest for both
kinds, EIP-1167 clones via the deterministic CREATE2 deployer (same address on Base and Ethereum).

**Status 10-03: written + 27 forge tests pass; not deployed.**

Change:
0. **Upgradeable, by owner signature only** (UUPS behind an ERC-1967 minimal proxy, OZ
   `ERC1967Clones`). The address is fixed by the factory + the first implementation + the key; the
   code can then move forward (spender "any way" guard, gas refunds, …) without anyone moving funds.
   An owner can already do anything, so this adds no new power; spenders can never upgrade.
1. **No squatting.** Salt = `keccak(qx, qy, kind, credentialIdHash)`; `initialize` checks it. A
   wallet can't be pre-deployed with the wrong kind or credential (v2 bug).
2. **Deploy + first call in one tx** (`Factory.createAndCall`). A bad signature reverts the whole
   thing, so no wallet is deployed that can't act.
3. **Per-signer nonces** (`nonces[signerId]`), so a passkey send and a pending wedgie request never
   collide.
4. **Real ERC-1271** `isValidSignature(bytes32, bytes)` for owners: sign-in-with-Ethereum, Permit2.
5. **One-tap login, no registry.** One assertion yields ≤4 candidate keys; with its `rawId` that's
   ≤4 candidate addresses. Pick the one that's known locally, deployed, or holds funds; a second
   Face ID only if still ambiguous. (An on-chain credentialId → wallet registry can be squatted.)
6. **Social recovery by guardians** (Austin, 10-03). A list of guardian addresses (default: only
   **dao.buidlguidl.eth** = `0xeF899e80aA814ab8D8e232f9Ed6403A633C727ec`, the same 4-of-8 Safe on Base
   and Ethereum). Any one guardian proposes replacing a key (lost phone or lost wedgie; the new key
   takes the old one's role) or adding an owner. An owner cancels it (any owner action does); if
   nobody does for 7 days, anyone finalizes. Owners can change the list and delay (min 1 day) or
   empty it. Replaces v2's "relayer EOA recovers everyone".
7. Low-s enforced off chain by both signers (OZ rejects high-s).

8. **Spender can move up to its daily limit any way** (Austin, 10-03): send, swap, bridge, dapp
   tx. `metaExecute` by a spender measures the wallet's balance of each limited asset before/after
   and reverts if the outflow exceeds what's left today; it also fails if the calls leave an ERC-20
   approval behind (an approval outliving the tx could drain past the limit). Hard part: assets with
   no limit (random tokens, NFTs) — a spender must not move them; design + tests before deploy.

Open: limits stay in base units per asset (no oracle). "$100/day" is exact for USDC; ETH limits are
set in ETH with the price shown at the time. A USD limit across assets = a later oracle question.

## Phase 1 — the instant wallet (next)

**Status 10-03:** `web/` built: create / log back in (one Face ID when the wallet is used), home with
every token on every chain, send (scan · 0x · ENS · USD toggle · max), receive (QR + pay link), links,
gas key (PRF or local). Local e2e (`web/tools/e2e.mjs`, virtual passkey, real on-chain WebAuthn checks)
passes. Not yet: WalletConnect + EIP-5792, deployment on Base/Ethereum, a real phone.

A new lean app replaces `packages/nextjs` (v2's AI, device queue, Capacitor, portfolio and Scaffold
deps are dropped; they stay in git history).

- **Open → Face ID → wallet.** One button, address known before any deposit. Returning: one tap.
  Port PSC `utils/passkey.ts` (create, recover, DER → low-s, challenge/type indices) and
  `browserEscape.ts` + `InAppBrowserBlock` (Instagram/Telegram webviews break WebAuthn).
- **Home** (punk wallet's one column): big balance (tap USD ⇄ token), assets on Base + Ethereum,
  your address QR with a blockie in the middle, floating scan button.
- **Send**: scan (stupid-simple-api-wallet's scanner: back camera, remembered) → parse in punk
  order (`http` link, `ethereum:` EIP-681 with chain/token/amount, `0x`, ENS) → amount in USD with a
  toggle → recipient's blockie shown → Face ID → sent by your gas key.
- **Receive / request**: QR with an EIP-681 amount; links `instantwallet.io/<net>:0xADDR;amount`
  compatible with punk wallet's, stripped from the URL after reading.
- **Sending is the product** (burner/punk wallet feel): scan or type `0x`/ENS, type amount, Face
  ID, sent. Nothing else in the way.
- **WalletConnect** (punk wallet `helpers/WalletConnectV2Helper.js`): a site shows a WC QR, the
  scan button on the phone reads `wc:` and connects. Dapp txs → proposal card → Face ID →
  `metaExecute`; `personal_sign` / `signTypedData` → ERC-1271 (item 4). Paste a `wc:` link too.
- **Gas: your own gas key** (Austin, 10-03). Each user has a small secp256k1 "gas key" EOA that
  submits their wallet's meta-calls and pays the gas; they put a little ETH in it. Derived from the
  passkey (WebAuthn PRF extension → same key on every synced device), localStorage fallback where
  PRF isn't supported. It holds only gas money and can't move wallet funds. Option: each call
  refunds gas to `msg.sender` from the wallet (v2's fee field), so it refills itself. First send
  deploys the wallet (`createAndCall`).
- **Hosting**: a Vercel URL for now (Austin adds the project); instantwallet.io when ready. The app
  must build on Vercel's own builders (v2's didn't).

Done when: Austin, on his phone at instantwallet.io, makes a wallet, receives, scans a QR and
sends a real token on Base and on Ethereum.

## Phase 2 — talk to your wallet

A mic button: say "send $20 to atg.eth" or "swap half my USDC to ETH on Base" → a proposal card
(what, to whom, which calls, fee) → Face ID (or the wedgie over the limit). The model never signs.
Source: **clawdbotatg/clawd-talk-to-your-wallet** (denar.ai): `packages/nextjs/app/api/intent/route.ts`
(19 wallet tools: portfolio via Zerion, swaps/bridges via LI.FI, prices, activity, security checks,
requote) and its `bridge/` (the same tools as a `claude -p` agent, subscription-billed, Bankr
fallback). v2's `/api/intent` was an earlier port of it. Output = calls `[{target, value, data}]`
that become a `metaExecute` digest; the card decodes them so you see what you sign.

## Phase 4 — the wedgie

An Instant Wallet cart in its own repo (`wedgie.json`, `usb: true`, Trust M), on the signed shelf.
- Keygen once (`optiga.Chip().genkey`), save the pubkey (the chip never gives it out again).
- `hello` → pubkey; `sign` → rebuild the EIP-712 digest from raw fields, show amount + recipient +
  fingerprint on wedgie.dev's `ui.page`, A signs / Y rejects, low-s fold, return `r, s`.
- Transport: **a laptop browser (Chrome) + the wedgie plugged into the laptop, over WebSerial**
  (Austin, 10-03). Phone ↔ wedgie (drive files, WedgieDrive app) comes later.
- Pairing = one passkey-signed batch: add wedgie as owner, demote passkey to spender, set limits.
- Over the limit → "confirm on your wedgie".

Risks: RP2040 RAM (~60–70 KB; 0.3.23 still crashes after plug-in on Austin's board); the drive path
has never carried a wallet request.
